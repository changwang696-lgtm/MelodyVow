# MelodyVow 关键生成链路与数据库基线

更新时间：2026-09-12

这份文档只记录不能反复改坏的核心事实。以后凡是改动首页生成、Showcase 播放、会员中心歌曲、Suno 回调、数据库持久化，都必须先对照这份基线。

## 一、两个关键生成逻辑

### 逻辑 1：生产环境回调链路

适用条件：
- `PUBLIC_BASE_URL` 已配置
- `https://api.melodyvowai.com/api/health` 返回 `callbackEnabled: true`

代码主链：
- 生成入口：`web/server/index.mjs:2167` `/api/generate-song`
- Suno 回调：`web/server/index.mjs:850` `handleSunoCallback`
- 结果标准化：`web/server/index.mjs:1266` `normalizeTracksFromRaw`
- ready 判定：`web/server/index.mjs:1309` `getNormalizedTaskState`
- 落盘同步：`web/server/index.mjs:486` `syncJobToAdminData`

必须满足的规则：
- 会员先登录，再生成
- 先扣点，再发起 DeepSeek 和 Suno
- 如果生成失败，必须退款
- Suno 回调收到后，如果还没有稳定音频链接，必须继续轮询，不能直接停在回调结果
- 只有在“状态完成 + 存在稳定音频链接”时，任务才允许进入 `ready`
- 不能把 `audiopipe.suno.ai` 这类临时流地址当成正式播放链接落库

### 逻辑 2：本地环境轮询链路

适用条件：
- `PUBLIC_BASE_URL` 未配置
- 本地健康检查返回 `callbackEnabled: false`

代码主链：
- 生成入口：`web/server/index.mjs:2167` `/api/generate-song`
- 轮询逻辑：`web/server/index.mjs:1443` `pollSunoTask`
- 结果标准化：`web/server/index.mjs:1266` `normalizeTracksFromRaw`
- ready 判定：`web/server/index.mjs:1309` `getNormalizedTaskState`

必须满足的规则：
- 本地没有回调时，任务必须靠轮询完成
- 即使 Suno 返回了 completed，如果没有稳定音频链接，也不能标记 `ready`
- 本地和线上的“稳定链接判定”必须完全一致，不能一套走临时链接，一套走正式链接

## 二、生成完成后的统一播放规则

前端统一规则：
- 电脑桌面端：首页生成成功后、会员中心点歌曲后，统一走 `FloatingPhonePlayer` 悬浮播放器
- 移动端手机端：首页生成成功后，跳到 `Showcase` 承接歌词、进度、自动播放
- 移动端手机端：会员中心点歌曲，也跳到 `Showcase` 统一播放
- 前端不要直接信任 Suno 原始链接
- 前端播放和下载统一走服务端代理地址

代码锚点：
- 首页提交后跳转：`web/src/App.tsx:2239` `HomePage`
- 手机端 Showcase 承接生成：`web/src/App.tsx:2852` `ShowcasePage`
- 服务端代理播放：`web/src/App.tsx:527` `getSongStreamUrl`
- 服务端代理下载：`web/src/App.tsx:523` `getSongDownloadUrl`
- 会员中心播放入口：`web/src/App.tsx:4043` `AccountPage`

硬规则：
- 电脑桌面端播放器逻辑固定为 `FloatingPhonePlayer`
- 移动端播放器逻辑固定为 `Showcase` 页面播放器
- 不允许手机端重新绕回浮动播放器处理新生成歌曲
- 不允许电脑桌面端误切到 `Showcase` 作为主播放器
- 不允许前端直接拿 Suno 临时地址做 `<audio src>`
- 歌曲历史、Showcase、后台播放链接必须同源，统一指向 `/api/songs/:songId/stream` 或 `/download`

## 三、移动端与桌面端职责边界

这是后续修改最容易出错的地方，必须先分清端，再改代码。

### 1. 播放器职责

桌面端：
- 主播放器固定为 `FloatingPhonePlayer`
- 相关代码锚点：
  - `web/src/App.tsx:1561` `upsertFloatingPlayer`
  - `web/src/App.tsx:1919` `FloatingPhonePlayer`
  - `web/src/App.tsx:3168` `buildFloatingPlayerPayloadFromJob`
- 桌面端需求如果是“悬浮播放器样式/行为/自动播放/切歌”，优先改这条链路

移动端：
- 主播放器固定为 `ShowcasePage`
- 相关代码锚点：
  - `web/src/App.tsx:3198` `ShowcasePage`
  - `web/src/App.tsx:3387` `syncShowcaseJob`
  - `web/src/App.tsx:3647` `Showcase audioEffect`
  - `web/src/App.tsx:3835` 之后的 `showcase-mobile-*` 结构
- 移动端需求如果是“生成进度、歌词、页内播放器、手机自动播放、手机列表点播”，优先改这条链路

### 2. 布局职责

桌面端布局：
- 默认样式、大屏布局、桌面展示逻辑，优先看基础样式与非移动端条件
- 若不是明确手机需求，默认先认为是桌面/共用层

移动端布局：
- 主要集中在 `web/src/App.css`
- 手机核心断点：
  - `@media (max-width: 720px)`：手机主布局
  - `@media (max-width: 1024px)`：平板/过渡层，共用修改前必须确认不会误伤桌面
- 页面级移动端样式主要看：
  - `.site-shell-showcase`
  - `.site-shell-account`
  - `.site-shell-home`
  - `.site-shell-pricing`
  - `.site-shell-styles`
- 手机 Showcase 播放器和歌词样式主要看 `.showcase-mobile-*`

### 3. 判断规则

遇到需求时先这样分流：
1. 如果需求关键词是“手机端 / 移动端 / 苹果浏览器 / Showcase 页内播放器 / 生成进度 / 歌词”，优先查 `ShowcasePage` 和 `showcase-mobile-*`
2. 如果需求关键词是“电脑桌面 / 悬浮播放器 / 浮动播放器”，优先查 `FloatingPhonePlayer`
3. 如果需求是“会员中心手机卡片 / 手机按钮 / 手机退出登录”，优先查 `.site-shell-account`
4. 如果需求是“全站导航手机排版 / 手机一行菜单”，优先查移动端断点和 `.site-shell-* .site-nav`

### 4. 修改禁忌

- 禁止把移动端播放器问题直接修到 `FloatingPhonePlayer`
- 禁止把桌面端播放器问题直接塞进 `ShowcasePage`
- 禁止在没有确认断点范围前，直接修改 `@media (max-width: 1024px)` 共用规则
- 禁止把“手机端专属 UI”写进桌面端通用样式里
- 禁止在没有确认当前需求所属端的前提下，修改全局播放器状态

## 四、数据库存储基线

数据库相关代码：
- 快照构建：`web/server/index.mjs:305` `buildPersistenceSnapshot`
- 持久化排队：`web/server/index.mjs:325` `queuePersistenceSync`
- 启动恢复：`web/server/index.mjs:2371` `bootstrap`
- Postgres 实现：`web/server/postgres-persistence.mjs`
- 表结构：`supabase/migrations/init_melodyvow.sql`

必须入库的核心数据：
- `members`
- `orders`
- `songs`
- `member_sessions`
- `generation_jobs`
- `lyric_requests`
- `suno_tasks`

必须成立的事实：
- 会员注册/登录后，会员和 session 必须能持久化
- 创建订单后，订单必须能持久化
- 生成歌曲时，任务、歌词请求、Suno 任务、歌曲记录必须都能持久化
- 后端启动时，如果 `DATABASE_URL` 有效，必须优先恢复远端 Postgres 状态
- 只有没有数据库时，才允许退回本地 JSON

## 六、支付现状基线

当前支付相关结论：
- 网站支付规划包含 `PayPal` 与“支付宝（国际）”
- 这两个支付通道目前仍在申请中
- 在申请完成并正式联调前，不能把支付功能视为完全上线闭环

现阶段必须记住的事实：
- 任何支付问题，先区分“支付通道尚未开通”还是“现有代码/订单状态流转出错”
- 在支付通道未正式可用前，禁止把“无法完成真实付款”直接判断成前端或数据库必然故障
- 一旦支付联调开始，必须同时检查：
  - 下单是否成功
  - 订单状态是否持久化
  - 支付完成后是否自动更新订单状态
  - 点数/会员权益是否正确发放
  - 支付失败或中断时是否避免误发权益

## 七、数据库安全与备份基线

数据库安全必须遵守：
- Supabase / Postgres 是生产事实来源，不能把本地 JSON 当作真实主库
- 涉及 `members / orders / songs / generation_jobs / suno_tasks / member_sessions` 的改动，必须优先考虑数据安全
- 任何修复都不能以“先删库再重建”作为默认方案
- 改动数据库结构、回调落库、订单状态、歌曲记录前，必须先确认现有数据不会被覆盖或误删

备份与恢复必须遵守：
- 所有生产级变更都要默认存在“可恢复”要求
- 至少要能明确回答三件事：
  1. 现在的数据是否已经持久化到 Supabase / Postgres
  2. 如果本次修改失败，如何回退代码而不破坏现有数据
  3. 如果出现异常，如何通过现有库数据恢复会员、订单、歌曲与任务状态

每次涉及数据库的改动后，至少复核：
1. `/api/health` 是否仍显示 `databaseEnabled: true`
2. 新注册/登录是否能落库
3. 新订单是否能落库
4. 新生成任务、歌词请求、Suno 任务、歌曲记录是否能落库
5. 服务重启后数据是否还能恢复

## 八、快速修复事项

以后网站出现问题时，优先按下面顺序快速排查，不要一上来只改前端：

### 1. DeepSeek / Suno / 回调快速检查

先确认：
- `/api/health` 中 `deepseekConfigured`、`sunoConfigured`、`callbackEnabled` 是否正常
- 生成入口 `/api/generate-song` 是否成功创建任务
- `pollSunoTask` 是否仍在运行
- `handleSunoCallback` 是否有收到并正确处理回调
- Suno 返回的是否是稳定音频链接，而不是 `audiopipe.suno.ai` 临时地址

如果出问题，优先恢复目标：
- 能正常创建任务
- 任务状态能持续推进
- 有稳定音频才能进入 `ready`
- 失败时能正确退款/回滚扣点

### 2. 支付快速检查

先确认：
- 当前问题是不是因为 `PayPal` / “支付宝（国际）”仍在申请中
- 下单接口是否正常
- 订单是否落库
- 订单状态是否被正确更新
- 支付成功后是否发放权益

### 3. 数据库快速检查

先确认：
- `/api/health` 中 `databaseEnabled` 是否为 `true`
- Supabase / Postgres 是否可连接
- 新会员、新订单、新歌曲、新任务是否真的写入数据库
- 服务重启后数据是否仍存在

### 4. 播放快速检查

先确认：
- 前端播放是否仍统一走 `/api/songs/:songId/stream`
- 下载是否仍走 `/download`
- 代理流是否支持 `Range/206`
- 移动端是否仍由 `Showcase` 接管播放，桌面端是否仍由 `FloatingPhonePlayer` 接管

快速修复的统一原则：
- 先恢复“可生成、可落库、可播放、可登录”
- 再处理 UI、提示文案、动效和视觉细节
- 任何修复都必须优先保护生产数据与订单数据

## 九、以后改动时的回归检查清单

每次改动下面任一模块后，必须至少核对这 8 项：

1. 首页点击 `Create My Song` 是否还能正常提交
2. 扣点失败时是否阻止生成
3. 生成失败时是否退款
4. `Suno completed` 但无稳定链接时，任务是否仍保持非 `ready`
5. 会员中心歌曲列表是否仍走 `/api/member/songs`
6. 播放和下载是否仍走 `/api/songs/:songId/stream` 与 `/download`
7. 线上 `/api/health` 是否仍为 `databaseEnabled: true`
8. 线上新生成歌曲是否不再出现 `audiopipe.suno.ai` 临时失效链接

## 十、禁止事项

- 禁止只改前端显示，不核后端真实链接来源
- 禁止只修某个页面，不核会员中心、Showcase、后台三处是否共用同一条播放链
- 禁止把“completed”直接等同于“可播放”
- 禁止忽略数据库真实状态，只看页面功能表面正常
- 禁止在没有重新核对这份文档前，继续叠加生成链路改动
