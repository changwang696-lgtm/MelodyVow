# MelodyVow 关键生成链路与数据库基线

更新时间：2026-09-10

这份文档只记录不能反复改坏的核心事实。以后凡是改动首页生成、Showcase 播放、会员中心歌曲、Suno 回调、数据库持久化，都必须先对照这份基线。

## 一、两个关键生成逻辑

### 逻辑 1：生产环境回调链路

适用条件：
- `PUBLIC_BASE_URL` 已配置
- `https://api.melodyvowai.com/api/health` 返回 `callbackEnabled: true`

代码主链：
- 生成入口：`web/server/index.mjs:2167` `/api/generate-song`
- Suno 回调：`web/server/index.mjs:850` `handleSunoCallback`
- 结果标准化：`web/server/index.mjs:1266` `normalizeTracksFromRaw`
- ready 判定：`web/server/index.mjs:1309` `getNormalizedTaskState`
- 落盘同步：`web/server/index.mjs:486` `syncJobToAdminData`

必须满足的规则：
- 会员先登录，再生成
- 先扣点，再发起 DeepSeek 和 Suno
- 如果生成失败，必须退款
- Suno 回调收到后，如果还没有稳定音频链接，必须继续轮询，不能直接停在回调结果
- 只有在“状态完成 + 存在稳定音频链接”时，任务才允许进入 `ready`
- 不能把 `audiopipe.suno.ai` 这类临时流地址当成正式播放链接落库

### 逻辑 2：本地环境轮询链路

适用条件：
- `PUBLIC_BASE_URL` 未配置
- 本地健康检查返回 `callbackEnabled: false`

代码主链：
- 生成入口：`web/server/index.mjs:2167` `/api/generate-song`
- 轮询逻辑：`web/server/index.mjs:1443` `pollSunoTask`
- 结果标准化：`web/server/index.mjs:1266` `normalizeTracksFromRaw`
- ready 判定：`web/server/index.mjs:1309` `getNormalizedTaskState`

必须满足的规则：
- 本地没有回调时，任务必须靠轮询完成
- 即使 Suno 返回了 completed，如果没有稳定音频链接，也不能标记 `ready`
- 本地和线上的“稳定链接判定”必须完全一致，不能一套走临时链接，一套走正式链接

## 二、生成完成后的统一播放规则

前端统一规则：
- 电脑桌面端：首页生成成功后、会员中心点歌曲后，统一走 `FloatingPhonePlayer` 悬浮播放器
- 移动端手机端：首页生成成功后，跳到 `Showcase` 承接歌词、进度、自动播放
- 移动端手机端：会员中心点歌曲，也跳到 `Showcase` 统一播放
- 前端不要直接信任 Suno 原始链接
- 前端播放和下载统一走服务端代理地址

代码锚点：
- 首页提交后跳转：`web/src/App.tsx:2239` `HomePage`
- 手机端 Showcase 承接生成：`web/src/App.tsx:2852` `ShowcasePage`
- 服务端代理播放：`web/src/App.tsx:527` `getSongStreamUrl`
- 服务端代理下载：`web/src/App.tsx:523` `getSongDownloadUrl`
- 会员中心播放入口：`web/src/App.tsx:4043` `AccountPage`

硬规则：
- 电脑桌面端播放器逻辑固定为 `FloatingPhonePlayer`
- 移动端播放器逻辑固定为 `Showcase` 页面播放器
- 不允许手机端重新绕回浮动播放器处理新生成歌曲
- 不允许电脑桌面端误切到 `Showcase` 作为主播放器
- 不允许前端直接拿 Suno 临时地址做 `<audio src>`
- 歌曲历史、Showcase、后台播放链接必须同源，统一指向 `/api/songs/:songId/stream` 或 `/download`

## 三、数据库存储基线

数据库相关代码：
- 快照构建：`web/server/index.mjs:305` `buildPersistenceSnapshot`
- 持久化排队：`web/server/index.mjs:325` `queuePersistenceSync`
- 启动恢复：`web/server/index.mjs:2371` `bootstrap`
- Postgres 实现：`web/server/postgres-persistence.mjs`
- 表结构：`supabase/migrations/init_melodyvow.sql`

必须入库的核心数据：
- `members`
- `orders`
- `songs`
- `member_sessions`
- `generation_jobs`
- `lyric_requests`
- `suno_tasks`

必须成立的事实：
- 会员注册/登录后，会员和 session 必须能持久化
- 创建订单后，订单必须能持久化
- 生成歌曲时，任务、歌词请求、Suno 任务、歌曲记录必须都能持久化
- 后端启动时，如果 `DATABASE_URL` 有效，必须优先恢复远端 Postgres 状态
- 只有没有数据库时，才允许退回本地 JSON

## 五、以后改动时的回归检查清单

每次改动下面任一模块后，必须至少核对这 8 项：

1. 首页点击 `Create My Song` 是否还能正常提交
2. 扣点失败时是否阻止生成
3. 生成失败时是否退款
4. `Suno completed` 但无稳定链接时，任务是否仍保持非 `ready`
5. 会员中心歌曲列表是否仍走 `/api/member/songs`
6. 播放和下载是否仍走 `/api/songs/:songId/stream` 与 `/download`
7. 线上 `/api/health` 是否仍为 `databaseEnabled: true`
8. 线上新生成歌曲是否不再出现 `audiopipe.suno.ai` 临时失效链接

## 六、禁止事项

- 禁止只改前端显示，不核后端真实链接来源
- 禁止只修某个页面，不核会员中心、Showcase、后台三处是否共用同一条播放链
- 禁止把“completed”直接等同于“可播放”
- 禁止忽略数据库真实状态，只看页面功能表面正常
- 禁止在没有重新核对这份文档前，继续叠加生成链路改动
